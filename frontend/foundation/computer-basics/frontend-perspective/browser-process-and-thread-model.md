# 浏览器进程和线程模型

## 核心答案

现代浏览器通常是多进程架构。常见会有浏览器主进程、渲染进程、网络进程、GPU 进程、插件进程等。前端代码最直接打交道的是渲染进程里的主线程，因为 JS 执行、样式计算、布局、绘制调度都和它强相关。

## 前端为什么会被问到这个

面试官想确认你是否理解“页面为什么会卡”“为什么 JS 不能无限占用主线程”“为什么 Web Worker 不能直接操作 DOM”这些问题背后的根因。

## 关键结构

- 浏览器主进程：负责标签页管理、地址栏、前进后退、界面协调。
- 渲染进程：负责解析 HTML、CSS，执行 JS，构建 DOM 和渲染页面。
- 网络进程：负责网络资源请求。
- GPU 进程：负责图层合成和图形加速。

## 渲染进程里常见线程

- GUI 渲染线程：负责布局、绘制。
- JS 引擎线程：执行 JavaScript。
- 事件触发线程：把事件回调推入任务队列。
- 定时器线程：管理定时器触发时机。
- 异步网络线程：处理资源加载完成通知。

## 面试时要说清的一句

JS 引擎线程和 GUI 渲染线程互斥，因此长时间执行 JS 会阻塞页面渲染，这就是主线程卡顿的根本原因。

## 常见追问

- 为什么 Web Worker 可以做计算但不能直接操作 DOM。
- `requestAnimationFrame` 为什么比 `setTimeout` 更适合动画。
- 长任务为什么会拖慢输入响应和首屏渲染。
