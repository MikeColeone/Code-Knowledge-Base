# 一次网络请求在浏览器和操作系统里发生了什么

## 核心答案

前端发起一次请求时，表面上只是调用 `fetch` 或 `XMLHttpRequest`，但底层会经过浏览器请求封装、网络进程、DNS 解析、TCP 或 TLS 建连、数据收发、回调调度，最后结果再回到渲染进程的主线程。

## 简化链路

1. 前端代码调用 `fetch`。
2. 浏览器把请求交给网络模块或网络进程。
3. 如有需要先走缓存和 DNS 解析。
4. 建立 TCP 连接，HTTPS 还要做 TLS 握手。
5. 请求发送到服务端，收到响应。
6. 浏览器解析响应头、处理缓存、跨域、安全策略。
7. 回调结果通过事件循环回到 JS 主线程。

## 前端为什么要懂这个

因为很多排障问题并不只是“接口慢”，而可能是 DNS 慢、TLS 慢、队头阻塞、缓存没命中、连接复用失败、主线程回调拥堵。

## 面试回答角度

- 先讲浏览器发请求不是 JS 自己直接和网卡通信。
- 再讲 DNS、建连、TLS、请求响应、回调调度几个阶段。
- 最后落到开发中怎么看瀑布图、怎么分辨慢在哪一段。

## 常见追问

- 为什么同域名连接数有限制。
- HTTP/2 多路复用解决了什么问题。
- 瀑布图里 `Stalled`、`DNS Lookup`、`Initial connection`、`TTFB` 分别代表什么。
