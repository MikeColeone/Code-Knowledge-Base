# 浏览器缓存链路

## 核心答案

浏览器缓存不是单点能力，而是一整条链路：从内存缓存、磁盘缓存，到 Service Worker、HTTP 强缓存、协商缓存，再到 CDN 和反向代理缓存。前端面试想听的不是名词罗列，而是你能不能讲清楚请求命中缓存的先后顺序和排障思路。

## 一个请求可能经过的缓存层

1. 浏览器内存缓存：最快，通常命中当前会话内的热点资源。
2. 浏览器磁盘缓存：关闭标签页后仍可能保留。
3. Service Worker 缓存：由业务控制，适合离线和精细化缓存。
4. HTTP 强缓存：例如 `Cache-Control: max-age`。
5. HTTP 协商缓存：例如 `ETag`、`Last-Modified`。
6. CDN 边缘缓存：减少回源和跨地域访问延迟。
7. 源站或反向代理缓存：提升后端吞吐。

## 前端视角怎么回答

- 先说浏览器本地缓存和 HTTP 缓存的区别。
- 再说强缓存和协商缓存的命中条件。
- 然后说为什么静态资源一般带 hash，接口数据一般更依赖协商或业务缓存。
- 最后说缓存失效、缓存穿透、发布后资源不更新怎么排查。

## 常见排障路径

- 看 DevTools 里资源状态是否是 `from memory cache`、`from disk cache` 或 `304`。
- 看响应头里的 `Cache-Control`、`ETag`、`Last-Modified`。
- 看 CDN 是否刷新、是否命中旧版本资源。
- 看 HTML 是否仍引用旧的构建产物地址。

## 常见追问

- 为什么 HTML 通常不做长期强缓存，而静态 JS/CSS 会配合 hash 长缓存。
- 首屏白屏时，缓存链路该怎么定位。
- Service Worker 更新为什么容易出现新旧资源不一致。
